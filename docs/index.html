Clinical cohort data, from raw file
to reproducible evidence

CohortStudio is a local-first application for observational cohort studies. Check the quality of your data, tick the criteria that define your analysis population, impute missing values for inference, run guided statistics and survival models, and hand over a Word study dossier that states what every result was computed on.

Workflow

One guided path, from the file to the report

The navigation follows the order of a study. Every step works on the same analysis population and records what it changed.

  1. 01

    Import

    CSV, Excel and Parquet files, with encoding, delimiter and decimal detection and a parse report.

  2. 02

    Validate

    Quality score, clinical anomaly rules, inclusion criteria, outliers and the participant flow.

  3. 03

    Enrich

    Merge external data, derive variables from formulas you type or the AI suggests, and impute missing values.

  4. 04

    Explore

    Descriptive statistics, correlations and interactive figures, exported as SVG or interactive HTML.

  5. 05

    Analyze

    Guided tests with a plan before you run them, effect sizes, regression and survival models.

  6. 06

    Reproduce

    Replay and check the trace, then export the Word report and the study dossier.

Features

Ready for the questions reviewers ask

Who was analysed, how the missing data were handled, which test was used and why, and whether the numbers can be reproduced.

Analysis population

One population, ticked in the sidebar, used everywhere

Inclusion, anomaly and outlier criteria are filters, not deletions. Tick or untick them and Explore, Analyze, Survival and Enrich all work on the same rows. Rows are removed only when you choose Keep only these rows on Validate, a traced step.

  • A participant flow diagram (STROBE item 13), with per-criterion counts and the reason for each exclusion
  • Every result is stamped with its data, its population and the N analysed
  • A result computed on another population is marked stale, never shown as current
Data validation guide

Data quality

A quality score you can act on

Six dimensions, from completeness to clinical validity, with weights you can adjust and a breakdown of where the score loses points, so you know where to look first.

  • Clinical anomaly rules you declare, such as an implausible weight or a height entered in metres
  • Outlier detection by IQR, z-score, Isolation Forest, local outlier factor or DBSCAN
  • Little's MCAR test and a scan of what predicts missingness
Researcher handbook

Describe and plot

Describe the data, then plot it the way your study needs

Explore sorts the columns by type and describes them: fill rate, quartiles and normality tests for the measurements, the most frequent values for the categories, and the correlations as a matrix or a network. Visualize then draws 14 kinds of figure on the same analysis population.

  • Box and violin plots with the p-value of each pair of groups, from Welch's t-test or Mann–Whitney, with a Bonferroni or Benjamini–Hochberg correction
  • Clustermaps that tag each variable by its p-value between groups, and correlation matrices clustered with their dendrograms
  • Themes and palettes, colour-blind-safe ones included; each figure downloads as SVG, as interactive HTML or with the rows behind it
Visualisation guide

Imputation

Missing data handled for inference, not hidden

A chained-equations engine modelled on R's mice: predictive mean matching, Bayesian normal, logistic and polytomous regression, and random-forest donors. It is fitted on the analysis population, and the outcome of the planned analyses always stays in the imputation model.

  • First, the values other variables determine are derived, not guessed: a formula fills a missing weight from the BMI and the height, typed or suggested by the AI engine, leaving fewer cells to impute
  • For figures and clustering, a quick single imputation (KNN, missForest, chained equations, mean or median), flagged in every result that uses it
  • Diagnostics (chain traces, R-hat, observed against imputed values), exports for R and Stata, and a methods paragraph following Sterne et al. (2009)
Enrichment and imputation guide

Guided statistics

See the plan before you run the tests

Choose the grouping variable and the outcomes: CohortStudio shows which test will run for each variable and why, then reports effect sizes with confidence intervals and adjusted p-values.

  • Welch's t-test and Welch ANOVA by default; assumption checks are diagnostics, not gates
  • Holm, Benjamini–Hochberg or Bonferroni corrections, explained in plain words
  • 2×2 tables, ANCOVA, diagnostic accuracy, kappa and ICC, McNemar, Mantel–Haenszel and power
Epidemiology and testing guide

Survival and regression

Survival and regression models, pooled across imputations

Kaplan–Meier curves, log-rank tests, Cox, logistic and Poisson or negative-binomial models run on the observed data or on every imputed dataset, combined with Rubin's rules.

  • Barnard–Rubin degrees of freedom, fraction of missing information and relative increase in variance for every term
  • The complete-case analysis next to the pooled one
  • Grambsch–Therneau proportional-hazards test and DeLong AUC

Reproduce and report

A study dossier you can hand over

Add any result to the dossier from the button under it. Reproduce › Study dossier downloads a Word document with the provenance, the participant flow, the data handling, the missing data and the results, each with what it was computed on.

  • A hash-chained trace, tamper-evident and checked when it is loaded
  • Headless replay that checks every step against its recorded fingerprint
  • Results computed on other data are left out, or kept and marked

Integrity verified: 3 chained steps, head hash dd466ba4e194b5d6. The trace is tamper-evident; it is not an electronically signed record.

Scientific rigour

Methods you can cite

Defaults follow current methodological guidance, and every method comes with its reference. The statistics package (biostats) is plain Python with no interface code, tested against R and published values.

Checked against R

The pooling, the D1 and D2 tests and the models fitted on R's completed datasets are compared with R mice 3.19 and mitml 0.4.5 on reference datasets generated by a CI workflow. A weekly simulation checks bias and coverage under data missing at random.

Missing data

  • Rubin's rules Rubin 1987
  • Barnard–Rubin degrees of freedom Barnard & Rubin 1999
  • D1 and D2 tests of several parameters Li et al. 1991; Reiter 2007
  • Chained equations as in mice van Buuren 2018
  • Little's MCAR test Little 1988

Group comparisons

  • Welch's t-test and Welch ANOVA Welch 1947, 1951
  • Games–Howell, Tukey HSD and Dunn post-hoc tests
  • Mann–Whitney with the Hodges–Lehmann shift Hodges & Lehmann 1963
  • Hedges' g with noncentral-t intervals Hedges 1981; Steiger 2004
  • Holm and Benjamini–Hochberg corrections Holm 1979; Benjamini & Hochberg 1995

Survival and regression

  • Kaplan–Meier with Greenwood intervals Kaplan & Meier 1958
  • Log-rank test Mantel 1966
  • Cox model with Efron ties Cox 1972; Efron 1977
  • Proportional-hazards test Grambsch & Therneau 1994
  • Logistic regression with DeLong AUC DeLong et al. 1988; Poisson and negative binomial with offsets

Epidemiology

  • Risk ratio, odds ratio and risk difference with the Haldane–Anscombe correction
  • Mantel–Haenszel estimates with the Breslow–Day test Mantel & Haenszel 1959
  • Incidence rates with exact Poisson intervals and rate ratios
  • Standardised mortality ratios

Diagnostics and agreement

  • Sensitivity, specificity and predictive values with Wilson intervals Wilson 1927
  • Likelihood ratios Simel et al. 1991 and the Youden index Youden 1950
  • Bland–Altman limits of agreement Bland & Altman 1986, 1999
  • Cohen's kappa and intraclass correlations

Reporting

  • Participant flow for STROBE item 13 von Elm et al. 2007
  • Multiple-imputation reporting items Sterne et al. 2009
  • Imputation guidance White, Royston & Wood 2011
  • The references of the methods used are collected in the dossier

Optional AI

An assistant that stays on your side

Install the ai group to add a document library you can question, a variable map of your study, and suggestions of new variables built from your columns. Ollama on your own server is the default. Cloud providers are opt-in and ask for your consent before any data is sent.

  • The statistics never depend on the assistant
  • Suggested formulas are checked against your columns, cite their source and are previewed before anything is added
  • Gemini, OpenAI, Mistral and Claude connectors, selectable in Settings
  • Documents indexed in LanceDB (embedded) or Qdrant
  • Without the group, the application runs and says which features need it

Architecture

Layered, tested and light to install

A Streamlit interface on a plain Python data and statistics engine. Tests check the direction of the dependencies, and the optional groups can be left out.

  • One write path. Every change to the data goes through one session object that records a trace step; nothing changes the data while a page is drawn.
  • A clean engine. Its statistics (biostats), file import (ingest) and data session (core) packages import no Streamlit, and core imports nothing above it. A layering test enforces both.
  • Light core install. The application runs without the ai, ml and survival groups; CI tests that minimal install in its own job.
  • Accounts and workspaces. Role-based accounts with bcrypt and login lockout, one workspace per user, and a first administrator created from a one-time setup token.

Install

Running in a few minutes

Python 3.14 with uv or pip, or a container. The core application needs none of the optional groups.

# Clone the repository
git clone https://github.com/KarimELMERNISSI/Cohort-Studio.git
cd Cohort-Studio

# Every optional group (ai, ml, survival); plain `uv sync` installs the core application
uv sync --extra all

# Start the application on http://localhost:8501
uv run streamlit run main.py
# Clone the repository
git clone https://github.com/KarimELMERNISSI/Cohort-Studio.git
cd Cohort-Studio

# Python 3.14 virtual environment (Windows: .venv\Scripts\activate)
python -m venv .venv
source .venv/bin/activate

# requirements.txt holds every optional group
pip install -r requirements.txt
streamlit run main.py
# Build and start; data, accounts and traces live in ./data
git clone https://github.com/KarimELMERNISSI/Cohort-Studio.git
cd Cohort-Studio
docker compose up -d --build

# First start: the log shows a one-time setup token for the administrator
docker compose logs cohortstudio
# Build the image (it installs every optional group)
docker build -t cohortstudio:latest .

# Run with a persistent data folder (add --env-file .env for your settings)
docker run -d -p 8501:8501 -v "$(pwd)/data:/app/data" --name cohortstudio cohortstudio:latest

# First start: the one-time setup token for the administrator
docker logs cohortstudio

Optional groups

ai adds the LLM connectors, the document library and the vector databases; ml adds MissForest (LightGBM), UMAP and FAMD; survival adds the proportional-hazards test and the concordance of the Cox model. all installs all three.

First administrator

Set CMP_ADMIN_USERNAME and CMP_ADMIN_PASSWORD in .env, or use the one-time setup token from the server log. Only a hash of the token is stored, and it stops working once used.
