# UI style guide

Conventions for every page of the platform. They exist so that a researcher can predict where
things are and what words mean, and so that results are reported the same way everywhere.

## Structure

- One H1 per page, rendered by `ui.components.page_header(title, subtitle, chapter=...)`. The header
  carries a one-line purpose and the link to the handbook chapter.
- Sections use `ui.components.section()` (H2). Never nest more than H3.
- Page-specific controls live in the page, not in the sidebar. The sidebar belongs to the shell:
  dataset card, AI status, handbook link, user menu.
- Empty states use `ui.components.no_dataset()`, `no_ai()` or `no_results()`; never a bare warning
  that points to a page by name.
- Destructive or shared-state actions (reset, reindex, delete, apply filter) go through
  `ui.components.confirm()`.
- Anything that runs longer than about two seconds runs inside `ui.components.long_op()`.

## Words

- Sentence case for labels, titles and buttons ("Load dataset", not "Load Dataset").
- Button verbs: Run, Apply, Save, Export, Import, Generate, Load, Rebuild, Clear.
- Do not call rule-based features "AI". "AI" refers only to the language-model features.
- Terms used on analysis pages must exist in the glossary (`ui/guidance/glossary.py`).
- Every input widget has a `help=` text that says what the choice changes (a test enforces this
  on the new modules).

## Reporting results

Every inferential result is rendered with `ui.components.result_card()` in this order:

1. the estimate on its original scale with its 95% confidence interval and the interval method;
2. the p-value, raw and adjusted (with the adjustment named), the statistic and degrees of freedom;
3. the sample sizes per group, the reference group and the comparison group;
4. the effect sizes with their intervals and Cohen's magnitude label;
5. assumption diagnostics as chips (ok / caution / violated); they never gate the analysis;
6. the method references;
7. a "How to read this" popover generated by `ui/guidance/interpretation.py`.

Wording rules (ASA 2016): a non-significant result is "no evidence of", never "no effect"; a
diagnostic that passes is "no evidence against", never "confirmed" or "validated"; power is
reported for a given sample size, never as "achieved power".

## Colour and theme

- Colours come from `.streamlit/config.toml` and `ui/theme.py` tokens; charts use the registered
  Plotly template (Okabe-Ito categorical palette, colour-blind safe).
- Status is never conveyed by colour alone: chips carry an icon and a word.
- Raw HTML (`unsafe_allow_html`) is not used in new code; native containers, badges and metrics
  cover the layouts needed.

## Multiplicity

Families are explicit: variables tested in one run (Holm by default), post-hoc pairs (intrinsic
to Games-Howell/Tukey, Holm for Dunn and pairwise tests) and screens (Benjamini-Hochberg).
Raw and adjusted p-values are both shown and labelled.
